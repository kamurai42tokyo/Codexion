Codexion ルール図解

コーダー（スレッド）がドングルを取り合いながら、コンパイル・デバッグ・リファクタリングを繰り返す課題のルールを、図でまとめたページです。

1円卓とドングル

コーダーとドングルは同じ数だけ用意され、円形に交互に並びます。各コーダーは、自分の左右にあるドングル2本を両方持ったときだけコンパイルできます。下の図は、コーダーが5人の例です。

  • コーダー（丸・数字は番号）
  • USBドングル（四角）
  • コーダー1は、コーダー5との間のドングルと、コーダー2との間のドングルの2本を使います。
  • 隣り合う2人のコーダーは、間にある1本のドングルを取り合います。
  • コーダーが1人だけのとき、机の上のドングルは1本だけです。そのコーダーはドングルを2本そろえられないので、コンパイルできません。

2コーダー1人の1周の流れ

どのコーダーも、下の4つの状態を決まった順番で回ります。矢印の横の等幅文字（例：is compiling）は、コーダーがその矢印を通るときに出すログです。

  • コーダーは、ドングルを1本取るたびに has taken a dongle を1行出します。2本そろったコーダーは、is compiling を出してコンパイルを始めます。
  • コンパイルを終えたコーダーは、ドングル2本を机に戻してからデバッグを始めます。
  • 机に戻されたドングルは、dongle_cooldown ミリ秒たつまで、どのコーダーも取れません。
  • リファクタリングを終えたコーダーは、ログを出さずに、すぐドングル待ちに戻ります。

3燃え尽き（burnout）の判定

各コーダーには、次のコンパイルを始めるべき締め切りがあります。締め切りは「最後にコンパイルを始めた時刻 + time_to_burnout」です。まだ1回もコンパイルしていないコーダーの締め切りは、「シミュレーション開始時刻 + time_to_burnout」です。

下の図の設定値：time_to_burnout = 800 / compile = 200 / debug = 200 / refactor = 200（単位はミリ秒）

燃え尽きが起きる3つのパターン

  1. ドングル待ちで間に合わない：隣のコーダーがドングルを使っている間、コーダーは待たされます。待っている間に締め切りを過ぎたら、そのコーダーは燃え尽きます。
  2. クールダウン待ちで間に合わない：机に戻されたドングルは、dongle_cooldown ミリ秒たつまで誰も取れません。その待ち時間で締め切りを過ぎた場合も、コーダーは燃え尽きます。
  3. 引数の値だけで間に合わない：time_to_compile + time_to_debug + time_to_refactor が time_to_burnout より長いと、コーダーは1周を終える前に締め切りを迎えます。この場合、コーダーはドングルを少しも待たなくても、デバッグ中やリファクタリング中に燃え尽きます。

4スケジューラ（fifo と edf）の違い

スケジューラは、複数のコーダーが同じ1本のドングルを待っているとき、どのコーダーに先にドングルを渡すかを決める規則です。1〜3で説明したルールは、fifo と edf のどちらでも同じです。

例：コーダー2とコーダー3が、2人の間にある1本のドングルを待っている場合（time_to_burnout = 800ms）

fifo（First In, First Out）

fifo のドングルは、先に頼んだコーダーから順に渡します。この例では、600ms に頼んだコーダー2が先にドングルを受け取ります。

edf（Earliest Deadline First）

edf のドングルは、締め切りが一番早いコーダーに先に渡します。この例では、締め切りが 800ms のコーダー3が先にドングルを受け取ります。

どちらのスケジューラでも変わらないこと

  • スケジューラは、あるコーダーが使っている最中のドングルを取り上げることはできません。
  • スケジューラは、dongle_cooldown の待ち時間を縮めることはできません。
  • 「引数の値だけで間に合わない」場合（3のパターン3）や、コーダーが1人だけの場合は、どちらのスケジューラでも誰かが燃え尽きます。

締め切りが同じコーダーが2人いた場合にどちらを先にするかの決まり（tie-breaker）も、課題文は edf に必要だとしています。

5シミュレーションの終了条件

シミュレーションは、次の2つのうち、先に起きたほうで止まります。

A. 誰か1人が燃え尽きた

どれか1人のコーダーが締め切りまでにコンパイルを始められなかったとき、シミュレーションは止まります。

B. 全員が規定回数に達した

1番から number_of_coders 番までの全員が number_of_compiles_required 回以上コンパイルし終えたとき、シミュレーションは止まります。1人だけが達しても止まりません。

6ログの読み方

各行は「経過ミリ秒 コーダー番号 メッセージ」の形です。経過ミリ秒は、シミュレーション開始からその行を出した時刻までの時間です。下の例は課題文（Mandatory part）のログ例です。
